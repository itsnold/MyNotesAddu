## Types of Errors

There are three categories of errors you'll encounter. Each shows up at a different stage.

> [!abstract] Error Types at a Glance
> | Type | When it shows up | Caught by |
> |---|---|---|
> | **Syntax** | Compile time | Compiler |
> | **Runtime** | During execution | JVM (crashes the program) |
> | **Logic** | During execution | You (output is wrong but no crash) |

---

### Syntax Errors

These are mistakes in the structure of your code. The compiler catches them before the program even runs.

> [!definition] Syntax Error
> A violation of the language's grammar rules. The program won't compile until all syntax errors are fixed.

> [!example] Common Syntax Errors
> ```java
> // Missing semicolon
> int x = 5     // ERROR: ';' expected
>
> // Mismatched braces
> if (x > 0) {
>     System.out.println("positive");
> // ERROR: missing closing brace
>
> // Wrong capitalization
> system.out.println("hello");  // ERROR: 'system' should be 'System'
> ```

---

### Runtime Errors

The code compiles fine, but something goes wrong while it's running. These cause the program to crash with an **exception**.

> [!definition] Runtime Error
> An error that occurs during program execution, typically causing the program to terminate unexpectedly (throws an exception).

> [!example] Common Runtime Errors
> ```java
> // Division by zero
> int result = 10 / 0;             // ArithmeticException
>
> // Accessing invalid index
> int[] arr = {1, 2, 3};
> System.out.println(arr[5]);      // ArrayIndexOutOfBoundsException
>
> // Null reference
> String s = null;
> System.out.println(s.length());  // NullPointerException
>
> // Bad number format
> int n = Integer.parseInt("abc"); // NumberFormatException
> ```

---

### Logic Errors

The program runs and doesn't crash, but the output is wrong. These are the trickiest to find because the compiler and JVM won't help you.

> [!definition] Logic Error
> A flaw in the program's logic that produces incorrect results. No error message is shown.

> [!example] Logic Error
> ```java
> // Trying to compute average
> int a = 10, b = 20;
> double avg = a + b / 2;        // avg = 20.0 (WRONG!)
> double avgCorrect = (a + b) / 2.0;  // avg = 15.0 (correct)
> ```
> The first version does `b / 2` first (integer division gives `10`), then adds `a`. Parentheses fix it.

> [!tip] How to find logic errors
> - Trace through your code manually with sample values
> - Use `System.out.println()` to print intermediate values
> - Use a debugger to step through line by line

## Exception Handling

Instead of letting runtime errors crash your program, you can **catch** them and handle them gracefully.

### The try-catch Block

Wrap the risky code in `try`, and handle the error in `catch`.

> [!info] Syntax
> ```java
> try {
>     // code that might throw an exception
> } catch (ExceptionType e) {
>     // what to do if that exception occurs
> }
> ```

> [!example] try-catch in Action
> ```java
> try {
>     int result = 10 / 0;
>     System.out.println(result);
> } catch (ArithmeticException e) {
>     System.out.println("Can't divide by zero!");
> }
> // Output: Can't divide by zero!
> // Program continues running normally after this
> ```

---

### The finally Block

Code inside `finally` runs **no matter what**, whether an exception was thrown or not. Good for cleanup tasks.

> [!info] Syntax
> ```java
> try {
>     // risky code
> } catch (ExceptionType e) {
>     // handle error
> } finally {
>     // always runs
> }
> ```

> [!example] finally Example
> ```java
> try {
>     int[] arr = {1, 2, 3};
>     System.out.println(arr[5]);
> } catch (ArrayIndexOutOfBoundsException e) {
>     System.out.println("Index out of range!");
> } finally {
>     System.out.println("This always prints.");
> }
> // Output:
> // Index out of range!
> // This always prints.
> ```

---

### Multiple catch Blocks

You can catch different exception types separately.

> [!example] Multiple Catches
> ```java
> try {
>     String s = "hello";
>     int num = Integer.parseInt(s);
>     int result = 10 / num;
> } catch (NumberFormatException e) {
>     System.out.println("Not a valid number!");
> } catch (ArithmeticException e) {
>     System.out.println("Math error!");
> }
> // Output: Not a valid number!
> ```

> [!warning] Order matters
> Catch the more **specific** exceptions first. If you put a general `Exception` catch first, the specific ones below it will never be reached (and the compiler will complain).

## Common Java Exceptions

> [!abstract] Exceptions You'll See Often
> | Exception | What causes it |
> |---|---|
> | `ArithmeticException` | Division by zero |
> | `NullPointerException` | Using a method on a `null` reference |
> | `ArrayIndexOutOfBoundsException` | Accessing an array index that doesn't exist |
> | `StringIndexOutOfBoundsException` | Accessing a string index that doesn't exist |
> | `NumberFormatException` | Converting a non-numeric string to a number |
> | `InputMismatchException` | Scanner gets wrong input type (e.g., letters when expecting `int`) |
> | `StackOverflowError` | Infinite recursion (too many method calls) |

---

## Throwing Exceptions

You can also throw exceptions yourself using the `throw` keyword.

> [!info] Syntax
> ```java
> throw new ExceptionType("message");
> ```

> [!example] Throwing an Exception
> ```java
> public static double divide(int a, int b) {
>     if (b == 0) {
>         throw new ArithmeticException("Cannot divide by zero");
>     }
>     return (double) a / b;
> }
> ```

> [!tip] When to throw
> Throw exceptions when your method receives invalid input or can't fulfill its contract. This makes your code more robust and easier to debug.
