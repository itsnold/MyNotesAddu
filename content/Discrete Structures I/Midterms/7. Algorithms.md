## Algorithm Definition and Properties

> [!definition] Algorithm
> An **algorithm** is a finite set of precise instructions for performing a computation or solving a problem.
>
> Every algorithm must have these properties:
> 1. **Input:** takes input values from a specified set
> 2. **Output:** produces output values from the input
> 3. **Correctness:** produces the *correct* output for each input
> 4. **Finiteness:** terminates after finitely many steps
> 5. **Effectiveness:** each step can be done exactly and in finite time
> 6. **Generality:** works for *all* problems of the desired form, not just specific cases

> [!info] Etymology
> The word "algorithm" traces back to the Persian mathematician **Al-Khowarizmi** (780-850 CE), whose name was Latinized to "Algoritmi."

## Pseudocode

Pseudocode is an intermediate step between an English description and actual code. It uses familiar programming constructs (loops, conditionals, assignments) but ignores strict syntax rules.

> [!tip] Why pseudocode over real code?
> - It's language-independent (not tied to Python, Java, C++, etc.)
> - Easier to read and analyze for correctness
> - Lets us focus on the *logic* rather than syntax details
> - Makes time complexity analysis simpler

The pseudocode in this course uses Pascal-like syntax:
- Assignment: `:=`
- Loops: `for`, `while`
- Conditionals: `if ... then`
- Return value: `return`

## Finding the Maximum Element

> [!example] Algorithm: Find the largest value in a list
> **Input:** a finite sequence $a_1, a_2, \ldots, a_n$ of integers
> **Output:** the largest integer in the sequence
>
> ```
> procedure max(a₁, a₂, ..., aₙ : integers)
>     max := a₁
>     for i := 2 to n
>         if max < aᵢ then max := aᵢ
>     return max
> ```
>
> **How it works:** Start by assuming the first element is the max. Go through the rest of the list; whenever you find something bigger, update your max. By the end, you've seen every element, so the stored max is truly the largest.

## Searching Algorithms

The **searching problem:** given a list of distinct elements $a_1, a_2, \ldots, a_n$ and a target $x$, find the index $i$ where $x = a_i$, or return $0$ if $x$ isn't in the list.

### Linear Search

The simplest approach: check each element one at a time, from left to right.

> [!definition] Linear Search
> ```
> procedure linear_search(x: integer, a₁, a₂, ..., aₙ : distinct integers)
>     i := 1
>     while (i ≤ n and x ≠ aᵢ)
>         i := i + 1
>     if i ≤ n then location := i
>     else location := 0
>     return location
> ```

> [!tip] When to use linear search
> - Works on **any** list (sorted or unsorted)
> - Simple to implement
> - But slow: has to check up to $n$ elements in the worst case

### Binary Search

A much faster approach, but requires the list to be **sorted in increasing order**.

> [!definition] Binary Search
> **Idea:** Compare the target with the *middle* element. If the target is bigger, search the upper half. If smaller, search the lower half. Repeat until you find it or narrow down to one element.
>
> ```
> procedure binary_search(x: integer, a₁, a₂, ..., aₙ : increasing integers)
>     i := 1          {left endpoint}
>     j := n          {right endpoint}
>     while i < j
>         m := ⌊(i + j) / 2⌋
>         if x > aₘ then i := m + 1
>         else j := m
>     if x = aᵢ then location := i
>     else location := 0
>     return location
> ```

> [!example] Trace: binary search for 19
> **List:** $1, 2, 3, 5, 6, 7, 8, 10, 12, 13, 15, 16, 18, 19, 20, 22$ (16 elements)
>
> | Step | Search range | Midpoint | Value | Action |
> |:---:|:---:|:---:|:---:|:---|
> | 1 | positions 1-16 | 8 | 10 | $19 > 10$, search upper half |
> | 2 | positions 9-16 | 12 | 16 | $19 > 16$, search upper half |
> | 3 | positions 13-16 | 14 | 19 | $19 \not> 19$, search lower half |
> | 4 | positions 13-14 | 13 | 18 | $19 > 18$, search upper half |
> | 5 | position 14 | - | 19 | Loop ends. $19 = 19$. Found at **position 14**! |
>
> Only 4 comparisons instead of 14 with linear search!

## Sorting Algorithms

The **sorting problem:** given a list of elements, rearrange them into increasing order.

### Bubble Sort

Makes multiple passes through the list. Each pass compares adjacent elements and swaps them if they're out of order. After each pass, the largest unsorted element "bubbles up" to its correct position.

> [!definition] Bubble Sort
> ```
> procedure bubblesort(a₁, ..., aₙ : real numbers with n ≥ 2)
>     for i := 1 to n - 1
>         for j := 1 to n - i
>             if aⱼ > aⱼ₊₁ then interchange aⱼ and aⱼ₊₁
> ```

### Insertion Sort

Builds the sorted list one element at a time. For each new element, find the correct position among the already-sorted elements and insert it there.

> [!definition] Insertion Sort
> ```
> procedure insertion_sort(a₁, ..., aₙ : real numbers with n ≥ 2)
>     for j := 2 to n
>         i := 1
>         while aⱼ > aᵢ
>             i := i + 1
>         m := aⱼ
>         for k := 0 to j - i - 1
>             aⱼ₋ₖ := aⱼ₋ₖ₋₁
>         aᵢ := m
> ```

> [!example] Trace: insertion sort on $[3, 2, 4, 1, 5]$
>
> | Pass | Element | Action | Result |
> |:---:|:---:|:---|:---:|
> | 1 | 2 | $2 < 3$, insert before 3 | $[2, 3, 4, 1, 5]$ |
> | 2 | 4 | $4 > 3$, stays in place | $[2, 3, 4, 1, 5]$ |
> | 3 | 1 | $1 < 2$, insert at front | $[1, 2, 3, 4, 5]$ |
> | 4 | 5 | $5 > 4$, stays in place | $[1, 2, 3, 4, 5]$ |

> [!tip] Bubble sort vs Insertion sort
> Both have $\Theta(n^2)$ worst-case complexity (covered in the Complexity section). Insertion sort tends to be faster in practice because it finishes early on nearly-sorted data.

## Exercises

> [!example] Exercise 1: Trace a binary search
> Search for $x = 7$ in the sorted list: $1, 3, 5, 7, 9, 11, 13, 15$.
>
> **Solution:**
> - **Step 1:** $i=1, j=8$, mid $= \lfloor 9/2 \rfloor = 4$. Value at 4 is $7$. $7 \not> 7$, so $j = 4$.
> - **Step 2:** $i=1, j=4$, mid $= \lfloor 5/2 \rfloor = 2$. Value at 2 is $3$. $7 > 3$, so $i = 3$.
> - **Step 3:** $i=3, j=4$, mid $= \lfloor 7/2 \rfloor = 3$. Value at 3 is $5$. $7 > 5$, so $i = 4$.
> - **Step 4:** $i=4, j=4$. Loop ends. $a_4 = 7 = x$. **Found at position 4.**

> [!example] Exercise 2: Bubble sort trace
> Sort $[5, 1, 4, 2, 8]$ using bubble sort.
>
> **Solution:**
> **Pass 1:** Compare adjacent pairs left to right.
> - $(5,1)$: swap $\to [1,5,4,2,8]$
> - $(5,4)$: swap $\to [1,4,5,2,8]$
> - $(5,2)$: swap $\to [1,4,2,5,8]$
> - $(5,8)$: no swap. 8 is locked.
>
> **Pass 2:**
> - $(1,4)$: no swap
> - $(4,2)$: swap $\to [1,2,4,5,8]$
> - $(4,5)$: no swap. 5 is locked.
>
> **Pass 3:**
> - $(1,2)$: no swap
> - $(2,4)$: no swap. 4 is locked.
>
> **Pass 4:** Single element left. Done!
> **Result:** $[1, 2, 4, 5, 8]$

> [!example] Exercise 3: When is linear search better than binary search?
> **Answer:** When the list is **unsorted**. Binary search *requires* a sorted list. If you have an unsorted list and only need to search it once, linear search is the way to go (sorting first would take $O(n \log n)$ which is worse than the $O(n)$ linear search). Binary search pays off when you search the same sorted list many times.
