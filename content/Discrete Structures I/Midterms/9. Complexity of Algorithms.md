## Time and Space Complexity

> [!definition] Complexity
> When analyzing an algorithm's efficiency:
> - **Time complexity:** how many basic operations (comparisons, additions, multiplications) it performs
> - **Space complexity:** how much memory it uses
>
> We focus primarily on **time complexity**, measured in terms of the number of operations as a function of input size $n$.

> [!tip] Why count operations instead of seconds?
> Measuring wall-clock time depends on hardware, programming language, compiler optimizations, etc. Counting operations gives a hardware-independent measure of efficiency.

---

## Worst-Case vs Average-Case

> [!definition] Worst-case and average-case
> - **Worst-case complexity:** the *maximum* number of operations over all possible inputs of size $n$. This is an upper bound on how bad things can get.
> - **Average-case complexity:** the *expected* number of operations, averaged over all possible inputs of size $n$. Often harder to compute.
>
> We primarily work with worst-case analysis, since it provides a guarantee.

## Complexity of Specific Algorithms

### Finding the Maximum

> [!example] Analysis of `max` algorithm
> The loop runs $n - 1$ times. Each iteration does:
> - 1 comparison for the loop condition
> - 1 comparison (`max < a_i`)
>
> Plus 1 final loop-exit check. Total: $2(n-1) + 1 = 2n - 1$ comparisons.
>
> **Complexity: $\Theta(n)$**

### Linear Search

> [!example] Analysis of `linear_search`
> **Worst case** (element is last or not in the list):
> - Each step checks two conditions: $i \le n$ and $x \neq a_i$
> - If not found: $2n$ comparisons in the loop + 1 to break + 1 final check = $2n + 2$
>
> **Average case** (assuming $x$ is equally likely at any position):
> - If at position $i$: takes $2i + 1$ comparisons
> - Average: $\frac{3 + 5 + 7 + \dots + (2n+1)}{n} = n + 2$
>
> **Complexity: $\Theta(n)$** (both worst and average case)

### Binary Search

> [!example] Analysis of `binary_search`
> **Worst case** (element not found):
> - The search interval halves each iteration: $n \to n/2 \to n/4 \to \dots \to 1$
> - If $n = 2^k$, this takes $k = \log_2 n$ iterations
> - 2 comparisons per iteration, plus a final check: $2\log_2 n + 2$
>
> **Complexity: $\Theta(\log n)$**

> [!tip] This is a massive improvement
> For a list of 1 million elements:
> - Linear search: up to **1,000,000** comparisons
> - Binary search: about **20** comparisons ($\log_2 10^6 \approx 20$)

### Bubble Sort

> [!example] Analysis of `bubblesort`
> - Pass 1: $n - 1$ comparisons (from $j = 1$ to $n - 1$)
> - Pass 2: $n - 2$ comparisons
> - $\vdots$
> - Pass $n-1$: 1 comparison
>
> Total: $(n-1) + (n-2) + \dots + 1 = \frac{n(n-1)}{2}$
>
> **Complexity: $\Theta(n^2)$**

### Insertion Sort

> [!example] Analysis of `insertion_sort`
> Worst case (list is in reverse order): comparing each new element against all previously sorted elements.
>
> Total comparisons: $2 + 3 + \dots + n = \frac{n(n+1)}{2} - 1$
>
> **Complexity: $\Theta(n^2)$**

### Matrix Multiplication

> [!example] Standard $n \times n$ matrix multiplication
> The product matrix has $n^2$ entries. Each entry requires:
> - $n$ multiplications
> - $n - 1$ additions
>
> Total: $n^3$ multiplications + $n^2(n-1)$ additions.
>
> **Complexity: $O(n^3)$**

> [!info] Boolean product has the same complexity
> The Boolean product of two $n \times n$ zero-one matrices: each of the $n^2$ entries needs $n$ ANDs and $n$ ORs = $2n$ bit operations per entry, giving $2n^3$ total. Still $O(n^3)$.

## Matrix-Chain Multiplication

When multiplying a chain of matrices $A_1 A_2 \dots A_n$, the **order of multiplication** makes a huge difference in efficiency (because matrix multiplication is associative but not commutative in cost).

> [!example] Associativity order matters!
> $A_1$ is $30 \times 20$, $A_2$ is $20 \times 40$, $A_3$ is $40 \times 10$.
>
> | Grouping | Operations | Total multiplications |
> |:---|:---|:---:|
> | $A_1(A_2 A_3)$ | $20 \times 40 \times 10 + 30 \times 20 \times 10$ | **14,000** |
> | $(A_1 A_2)A_3$ | $30 \times 20 \times 40 + 30 \times 40 \times 10$ | **36,000** |
>
> The first grouping is **2.5x faster**! Dynamic programming is used to find the optimal ordering.

## Algorithmic Paradigms

> [!info] Common algorithmic paradigms
> - **Brute-force:** try all possibilities. Simple but often slow. Examples: linear search, bubble sort, checking all pairs of points for closest pair ($\Theta(n^2)$).
> - **Greedy:** make the locally optimal choice at each step, hoping it leads to a global optimum.
> - **Divide and conquer:** split the problem into smaller subproblems, solve recursively, combine results. Example: merge sort ($O(n \log n)$), closest pair in $O(n \log n)$.
> - **Dynamic programming:** break into overlapping subproblems, store results to avoid recomputation. Example: matrix-chain multiplication.
> - **Backtracking:** explore possibilities systematically, abandoning paths that can't lead to a solution.
> - **Probabilistic:** use random choices to guide the algorithm (sometimes faster on average).

## Complexity Terminology

| Complexity | Name | Practical? |
|:---|:---|:---:|
| $\Theta(1)$ | Constant | Yes |
| $\Theta(\log n)$ | Logarithmic | Yes |
| $\Theta(n)$ | Linear | Yes |
| $\Theta(n \log n)$ | Linearithmic | Yes |
| $\Theta(n^2)$ | Quadratic | Moderate |
| $\Theta(n^3)$ | Cubic | Gets slow |
| $\Theta(2^n)$ | Exponential | Impractical for large $n$ |
| $\Theta(n!)$ | Factorial | Impractical for large $n$ |

> [!warning] Exponential and factorial algorithms are essentially useless for large inputs
> For $n = 100$: $2^{100} \approx 1.27 \times 10^{30}$ operations. Even at a billion operations per second, that's about $4 \times 10^{13}$ *years*.

## P vs NP

> [!definition] Problem classes
> - **Tractable:** solvable in **polynomial time** (belongs to class **P**)
> - **Intractable:** no polynomial-time algorithm exists
> - **Unsolvable:** no algorithm exists at all (e.g., the Halting Problem)
> - **Class NP:** solutions can be *verified* in polynomial time, but no polynomial algorithm is known to *find* them
> - **NP-Complete:** the "hardest" problems in NP. If you find a poly-time algorithm for any one of them, every NP problem becomes poly-time solvable.

> [!abstract] The P = NP? question
> **Does P = NP?** Can every problem whose solution is *checkable* in polynomial time also be *solved* in polynomial time?
>
> - No one has proved it either way
> - Most experts believe **P $\neq$ NP**
> - It's one of the seven **Clay Millennium Prize Problems** (worth \$1 million)
> - Finding no polynomial algorithm so far does NOT prove one doesn't exist

## Exercises

> [!example] Exercise 1: What is the time complexity of this code?
> ```
> for i := 1 to n
>     for j := 1 to n
>         x := x + 1
> ```
>
> **Solution:** The inner loop runs $n$ times for each of $n$ iterations of the outer loop. Total: $n \times n = n^2$ additions.
> **Complexity: $\Theta(n^2)$**

> [!example] Exercise 2: What about this one?
> ```
> for i := 1 to n
>     for j := 1 to i
>         x := x + 1
> ```
>
> **Solution:** When $i = 1$: 1 operation. When $i = 2$: 2 operations. $\dots$ When $i = n$: $n$ operations.
> Total: $1 + 2 + \dots + n = \frac{n(n+1)}{2}$
> **Complexity: $\Theta(n^2)$**

> [!example] Exercise 3: Compare search complexities
> You have a sorted list of 1,000,000 elements. How many comparisons does each search take in the worst case?
>
> **Solution:**
> - **Linear search:** up to $2(1{,}000{,}000) + 2 = 2{,}000{,}002$ comparisons. That's $\Theta(n)$.
> - **Binary search:** at most $2\lfloor\log_2 1{,}000{,}000\rfloor + 2 = 2(19) + 2 = 40$ comparisons. That's $\Theta(\log n)$.
>
> Binary search is about **50,000 times faster** here.

> [!example] Exercise 4: Matrix multiplication chain
> $A_1$ is $10 \times 20$, $A_2$ is $20 \times 5$, $A_3$ is $5 \times 15$.
>
> **Solution:**
> - $A_1(A_2A_3)$: $(20)(5)(15) + (10)(20)(15) = 1500 + 3000 = \textbf{4500}$ multiplications
> - $(A_1A_2)A_3$: $(10)(20)(5) + (10)(5)(15) = 1000 + 750 = \textbf{1750}$ multiplications
>
> The second grouping is better here, saving over 60% of the multiplications!
